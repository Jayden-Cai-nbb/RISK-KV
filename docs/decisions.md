# 关键设计决策

| 决策 | 依据与推理 | 当前实现与后续检验 |
| --- | --- | --- |
| 管理控制优先，复用PicoRV32/openTPU | 工作目标是共享对象的持续服务；重写算术单元会改变数值与资源基线 | 保留完整模型和原生格式；数据通路优化需瓶颈证据 |
| 完成消费后提交 | HALT、写回接受、存储退休和软件消费并非同一事件 | 身份匹配ACK才推进BUILD/DECODE进度；覆盖延迟消费与竞争 |
| 整区清理作为首版基线 | 残留尺度、NaN及非零工作区初值会影响再次服务 | 双尾/整对象清理加模板恢复；局部清理单独实验 |
| 取消采用自然结束与排空 | 原计算引擎没有已验证的抢占式停止合同 | 取消阻止逻辑提交，保留物理责任；取消时延是后续优化项 |
| 普通CPU复位与整链复位分开 | 清掉控制寄存器无法撤销DDR和跨域队列中的请求 | 独立监督器排空清理，失联进入隔离，冷启动重建资格 |
| 主机装载与计算互斥 | 活动KV/权重被主机并发改写会破坏任务一致性 | 准入从最早接收入口锁定责任，完成前不得切换所有者 |
| 真实写掩码由硬件实现 | JTAG窄访问能力不能直接覆盖全部掩码语义 | AW沿锁存掩码，W阻塞时稳定，B消费后释放责任 |
| 固定48 MHz单级MIG适配 | 实测参考约48 MHz；板上重新插紧Kingston后同配置读写成功 | 冻结已工作的参数，采用实验支持范围，停止无依据参数扫描 |
| 参考与候选使用不同KV布局 | 可暴露共享地址映射错误 | 上游算术/编译器仍有共同依赖，未来增加独立算子级检查 |
| 同一最终位流重新验收 | 独立DDR位流成功不能覆盖完整NPU加入后的布局和时序变化 | 最终位流重新做DDR、数值、持续服务及异常验收 |

## 促成设计变化的关键发现

**早期主机准入。** 路由缓存地址可能先承担请求责任，而下游尚未表现为busy。准入因此以最早接收事件和持久在途状态共同判断，避免计算抢先启动。

**迟到响应与内容资格。** 传输超时后，即使物理通道后来排空，也不能直接把旧响应当作下一次读取。持久主机journal记录未知事务，恢复需要显式整链重配及内容重新校验。

**跨域复位释放。** 完整平台时序审查发现core来源的冷复位直接进入DDR域复位端点。当前实现增加每域三级同步释放，再保留延展和双向确认。具体异步入口有逐端点约束，业务路径继续参与时序分析。

**板级接触因素。** 原Kingston重插并重启后，同一DDR参数获得校准与读写正例。该结果支持连接因素参与故障，但重插与重启同时发生，不能据此唯一归因。后续以固定配置的重复校准和全范围数据测试建立稳定性证据。

这些记录保存影响架构的判断依据及采用标准；逐轮工具输出保存在工作区归档中。
