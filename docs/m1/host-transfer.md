# JTAG 装载链路与长期吞吐

## 问题与实测

最终整机 DDR 资格通过后，主机冷镜像装载暴露出持续会话中的吞吐退化。原路径首个 1 MiB 写入约 3 秒，累计约 169 MiB 后达到约 100 秒；读回仍约 2 秒。已读回的数据均与镜像一致，CPU 始终处于 `boot_hold`。这属于装载阶段的主机传输问题，不能解释为 DDR 或 NPU 的运算性能。

`board-suite-v2` 在已校验 177209344 字节后主动停止。下一笔 1 MiB 写请求未确认退休，原持久状态记录进入隔离并保留请求身份。随后显式配置同一位流，建立新的冷启动身份；已装载的部分镜像不赋予运行资格。

## 定位与修改

在独立 Tcl 副本中，对事务创建、AXI 执行、状态刷新、数据检查、删除和 RPC 边界分别计时。事务创建没有出现与原退化相符的增长，AXI 执行维持约 1.4–1.8 秒/MiB。额外开销集中于大字符串处理与报文边界；普通管道读入微测没有复现退化，单纯将变量移入局部作用域也没有解决切片开销。

保留原有一笔在途事务、地址和字序、响应校验及异常隔离合同，修改主机 Tcl 的两个位置：

1. 完整校验输入后，将十六进制载荷一次转换为字节数组，以 `binary scan` 按偏移取出每个突发的数据，避免反复处理整个大字符串。
2. RPC 帧通过独立的 `/dev/stdout` 二进制通道写入父进程管道。Python 继续保存原始输出与请求/响应日志；Vivado 常规日志保留工具诊断。此入口针对当前 Linux 主机。

两项修改组合的实物效果已经测量；尚未将累计退化精确归因于 Vivado 内部的某一实现机制，不据此宣称工具内部缺陷已得到证明。没有修改位流、MIG 参数、模型、固件、超时上限或数值比较标准。

## 回归与证据

连续 32 MiB 真实镜像写入及完整读回通过。每个块的读回摘要同时在本机与镜像源文件核对。随后回收65项精选原件并核对摘要，在本机独立解析32次写入与32次读回的完整RPC数据，与本机冷镜像逐字节一致。

| 指标 | 实测值 |
| --- | --- |
| 前段 8 块写入中位数 | 1.925 秒/MiB |
| 末段 8 块写入中位数 | 1.724 秒/MiB |
| 最大单块写入时间 | 2.597 秒 |
| 全部读回中位数 | 1.945 秒/MiB |
| 数据比较 | 32 MiB 全部一致 |

Tcl 桩覆盖跨 4 KiB 边界、64-bit 字序、最大 1 MiB 报文、非周期数据、最后一个字符非法时在写入前拒绝、快照及控制接口。原有 10 项 Python 传输与持久隔离测试通过。诊断结束时没有存储在途，镜像资格仍为 `UNKNOWN`，之后重新执行完整装载。

本次证据目录为 `build/reproduction/g3-board-final-20261107/transfer-analysis-v1/`。`durations.json` 保存原退化曲线；`profile-session/profile.tsv` 保存分项计时；`candidate-results.json` 保存逐块结果；`candidate-session/requests.jsonl` 保存全部候选读写原件。精选原件归档及逐文件摘要见同级 `transfer-evidence-v1.tar.gz` 与 `transfer-evidence-manifest.json`。

32 MiB 稳定性回归用于批准继续完整装载。2026-11-08，`board-suite-v3/load`完成全部1,610,710,400字节冷镜像写入和读回，耗时5759.070秒；加上三个工作区模板，共1,616,000,768字节、5778.106秒。全部读回摘要已与本机冷镜像及模板源区域再次核对。这一结果取代原短块外推，记录的是包含状态观察和主机处理的实际装载时间。四-token完整检查及后续连续服务以各自报告为准。
